# Flap 提前信号通知精度修复

版本：Monitor Suite 1.12.12 / Flap 1.10.11。

## 实测原因

2026/9/28 09:34:20—10:34:20（北京时间），飞书读取确认共 69 张提前信号卡：32 张小额 BNB 余额扣减、26 张加减流动性及配套转账、7 张授权、4 张陌生代币被动转入。链上共 37 笔交易；抽查两次余额减少与对应交易 Gas 完全相等。上述时间窗未发现新增 CoW 订单、包装或开放提案事件。

原逻辑按原始事件直接入队，已开放资产仍称为提前信号；同一交易按资产拆段，余额变化再单发。无关方转币也能生成观察卡。此处是通知筛选与表达问题，不能通过降低扫描频率修复。

## 保留原则

- 所有监控间隔、确认块数、扫描游标、节点预算、Safe API 策略不变；不新增正常 RPC 查询。
- 原始事件、候选跟踪及配置复核均保留；只改变通知时机与分组，遵循原有事件保留上限。
- 未开放／状态未知资产的首次主动动作、采购和每次成交进展、包装、所有加池与撤池、提案、权限、配置变化、直接 BNB 转账、未知事件即时排队。
- 余额增加、超过 0.0001 BNB 的单次扣减、不能解析的余额变化即时排队。小额扣减五分钟汇总；金额匹配不能排除其他资金流，因此没有盲目静默“Gas”。
- 仅明确被动收币、已确认开放且近期复核正常的单独 LP 授权，以及小额扣减延期汇总。未知授权对象、额外资金收款方、已有 NFT 转出仍即时排队。
- 首次观测资产不能因稍后的 getter 返回已开放而被追溯改成普通通知。字段缺失的旧记录保守处理。
- 汇总与即时通知公平排队，十秒计时器保证所有来源退避时仍检查到期通知；网络故障不保证五分钟送达。
- 交易不可被八条日志的旧批量边界截断。交易链接只显示一次；“本次动作”与资产“当前状态”分开，撤池和资金变化采用明确标题。
- CoW 部分成交每次仍通知，并补充累计买入／卖出原始数量，避免正文看起来完全重复。
- 发送计划、稳定 delivery ID、成功分片和待处理事件一起落盘。失败、重启、并发到达新事件都不得提前确认未送达记录。

## 验证范围

测试覆盖即时事件白名单及未知类型的保守默认、资产首次观察与缓存失效、收币后主动转出、额外收款方、余额正负与边界、整笔交易超过八条日志、汇总公平排队、失败及重启后的分片续发。真实链上回执用于验证加池、撤池、被动收币和历史余额样本。

1.10.10 初版验证：本地 `npm run check` 和全量 438 项测试通过。回放三笔真实交易回执（BILIon 加池、SGOVon 撤池、陌生代币转入）及此前 32 次余额扣减，共 41 条事件：撤池的三条关联证据即时送入同一通知，余下 38 条进入两批日常汇总；41 条均被选中且无重复，原始记录全部保留。回放采用已核实开放的资产快照，并模拟正常的周期配置复核；这是样本验证，不是长期零漏报保证。

本次不改变 RPC 供应商与查询调度。审计窗口仍发现实时日志请求间歇限流，通知优化不能宣称解决公共节点可用性问题。

## 1.10.11 加池即时通知修正

按用户要求，所有捕获的加池事件均即时通知，包括已开放资产的常规加池；按用户补充要求，加池卡只展示加池动作，不展示同交易的配套转账、授权和 LP NFT 明细；原始证据继续保留，随加池卡成功发送后确认，避免另行刷屏。混合交易中的撤池、权限和提案等独立重要事件仍显示。移除不再可达的日常加池判断。已在队列中等待汇总的加池记录下轮重新分类，不清队列或重播已确认记录。采集范围、频率和确认块数保持不变。回归用例明确验证已开放资产加池无需等待五分钟，且配套转账不展示、原始证据仍保留。
