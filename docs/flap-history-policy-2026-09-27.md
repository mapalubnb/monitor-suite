# Flap 单节点日志与旧合约历史调整

版本：Monitor Suite 1.12.9 / Flap 1.10.8。

## 用户确认的范围

- Flap 历史 `eth_getLogs` 空结果采用首个成功节点，非空结果原本就是单节点。异常响应、限流、超时仍切备用；实时空结果保留节点高度校验。
- 放弃合约完整性当前未扫旧区间 `117817600–123897319`（原游标为 `117817599`）。不更改 Factory、金库注册、提前信号等其他模块的历史区间。
- 所有监控间隔、确认块数、RPC 池/预算和 Safe API Key 策略不变。合约状态检查、实时日志、WSS 及未来缺口自动补扫继续运行。

## 实现与影响

`queryBscLogs` 不再为历史空结果寻找第二个独立来源，减少这类查询的重复请求和等待；不保证公共节点不会限流。首节点错误返回空数组可能导致该区间漏扫，是本次单节点策略的取舍。

一次性工具严格匹配指定的整个活动区间，若进度已变化或待补队列与目标重叠则拒绝写入。写入前完整备份原状态，保留实时游标、合约目录、待通知事件及其他缺口，增加 `historyAbandonments` 审计记录。重复执行已处理区间不会改变后续任务。不在进程启动时自动执行，不永久关闭补扫任务。

`fl-status` 显示“已放弃旧补扫：… · 未扫描；后续缺口仍自动补扫”。放弃区间不能解释为扫描完成，该区间未发现的历史事件及可能由事件发现的合约不再回查。

## 操作

必须先推送 GitHub，再由服务器拉取并验证代码。状态写入必须在 Flap 完全停止后执行，防止运行进程覆盖文件；其他模块无需停止。

```bash
pm2 stop flap-monitor
node flap-monitor/abandon-contract-history.mjs flap-monitor/contract-integrity-state.json 117817600 123897319
node flap-monitor/abandon-contract-history.mjs flap-monitor/contract-integrity-state.json 117817600 123897319 --apply
pm2 restart flap-monitor
pm2 save
```

工具返回实际备份路径。若预览拒绝，应重新核对当前区间，不能盲目替换参数。需要恢复旧区间时，应停服并按备份中的区间定向恢复；不要直接覆盖已新增的实时状态、通知或合约目录。
