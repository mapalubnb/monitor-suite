## 写入占用与交接

1. 所有仓库写入前，先用 `git rev-parse --absolute-git-dir` 获取 Git 目录，并检查 `git status --short`。
2. 用 Node `fs.mkdirSync(lockPath)`（**不带 recursive**）原子创建 Git 目录下的 `monitor-suite-write.lock`。`EEXIST` 表示已有写入者，不能覆盖。取得占用后创建 `owner.json`，写明对话 ID、职责、修改范围、开始时间；不写凭证。
3. 原子目录创建是互斥依据，文档中的“正在处理”文字不是锁。占用目录不进入 Git；它只协调同一工作目录，服务器变更由取得写锁的当前执行对话完成。
4. 锁存在时先读取所有者。保持只读，可以分析或准备方案；不要仅凭锁的年龄删除它。确认所属任务已结束/取消且没有写入后，由当前执行对话核实所有者任务状态后恢复遗留占用。
5. 结束时只删除自己创建的 `owner.json`，再用 `fs.rmdirSync(lockPath)` 删除空目录；所有者不符或目录内有未知文件时不删除，不使用递归强制清理。
6. 模块工作结束后更新 HANDOFF 的“发布记录”，列出全部预期改动及验证证据，再释放占用。工作区有待发布改动时，后续写入由当前任务对话继续至发布验收完成；其他模块先做只读工作。
7. 执行对话取得占用后，核对 diff 与交接范围，只暂存本次已审查文件。不能用“提交全部”顺带收录其他对话工作。需要发送跨对话消息时先核对用户是否明确授权；默认读取版本化任务记录，不自动互发消息。

初始化工作由执行对话取得占用，完成文档提交、服务器同步和对话登记后释放。锁状态始终以文件系统为准，不将本文件作为持续占用标记。
