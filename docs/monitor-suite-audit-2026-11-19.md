# Monitor Suite 代码与性能审查

审查基线为 Suite 1.12.99、Four.meme 1.5.38、Flap 1.10.57（`b446150`）。本轮修复已发布为 Suite 1.12.100 / Four.meme 1.5.39（业务提交 `81b2edb`），修复 Four.meme 轻量探测挂起，并减少快照写入的重复计算。轮询、超时设定值、确认块、交易逻辑和过滤条件沿用生产配置。Flap 和机器人进程本轮继续运行。

三项 Flap 问题已在 Suite 1.12.101 发布修复，见[上线验收](../flap-monitor/HANDOFF.md)。

## 共用基础设施与代码质量

- **P1 已修复，快照重复计算。** 内容寻址存储对已编码且完全相同的大分片复用原字节分类和 SHA256，保留新内容的阈值判断、校验、清单原子发布和重启语义。此变更不会减少 Flap 独立整文件快照的写入。
- **P2，RPC 复用。** 两边已有并发预算、冷却和不同用途的端点。优先验证相同区块哈希、相同请求参数和相同校验要求下的复用。零确认头块、重组、同轮复核和不同端点故障域继续各自校验。
- **P2，飞书和运维。** 机器人在线，日志已有真实 `fm-status` 和 `fl-status` 指令及去重记录。Four.meme 重启后由正常启动流程恢复连接；本轮无额外人工测试卡。待发、发送、编辑和过期错误应独立统计。
- **P3，依赖与遗留逻辑。** 七项直接依赖均有生产运行或修复工具引用，`stream-json` 服务于离线状态压缩工具。未发现可直接移除的声明依赖。仍可清理没有生产入口的旧 GitHub 轮询以及只用于测试的序列化入口，先将其有价值的覆盖迁入现行入口。
