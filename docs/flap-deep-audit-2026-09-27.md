# Flap 深度检查与修复（2026-09-27）

版本：Monitor Suite 1.12.8 / Flap 1.10.7。时间均按北京时间解释。

## 生产证据与根因

- Flap 在 00:17:58、06:39:12、12:58:08 被 PM2 自动拉起；错误日志为 JavaScript heap out of memory，崩溃前完整 GC 后仍约 944–950 MiB。
- 服务器运行 Node.js 22.23.1。RPC 排队使用 `AbortSignal.any([signal, AbortSignal.timeout(3000)])`，在该版本上可稳定复现取消信号保留。不是 RPC 逻辑队列数量或业务状态文件体积可以解释的增长。
- 同版本独立实验执行 30000 次请求：旧组合路径多轮 GC 后约 72.1 MiB，对照请求约 8.5 MiB；去掉组合信号的诊断版本约 8.8 MiB。仅创建/取消组合信号的最小实验也会保留约 60000 个 AbortSignal 和 30000 个 DOMException。
- CoW 9 个地址成功时间停在 15:32，16:31 仍未更新；独立 API 探测 HTTP 200 / 254 ms。旧 API 读取仅依赖传输 abort，缺少独立结束等待的期限。
- 状态文件：合约约 2.04 MB、提前信号约 0.385 MB、Factory 约 0.248 MB、Safe 约 0.061 MB。各通知队列无积压。

## 修复范围

1. 新增 `shared/request-deadline.mjs`，手动转发取消并显式清理定时器和监听器，避免组合信号；RPC 独立请求期限、3 秒排队期限与备用竞速取消保留。
2. CoW、Safe、页面和 GoPlus 的网络请求及响应体采用独立截止时间；传输不响应取消也能结束本轮。Safe 保留原账户选择、请求间隔、配额及失败冷却；取消后迟到响应不再写入配额。RPC 迟到结果不再更新节点冷却，HTTP 错误避免重复记账。
3. 链上提交保留正在执行的 Safe 关联发现进度对象，避免克隆替换导致分页进度丢失和重复查询。
4. 实时、补扫、快速回执合入池子元数据时只补缺失记录；重放建池事件保留已核验的官方参与证据。
5. 通知队列容量错误必须上抛，不得作为一般解码错误吞掉并继续推进游标。
6. 独立调度任务记录开始、结束、运行状态；`fl-status` 显示长期未完成/未调度、运行指标停止更新，以及 CoW 各地址成功时间范围。每日关联发现与无事件的快速通道不会仅因业务成功时间旧而误报。

## 未改变的监控参数

未修改 `.env`、确认块数、RPC 池和供应商预算。发布前记录的主要间隔：页面 1000 ms；Factory 实时 500 ms、历史/补扫 1000 ms；合约核心 10000 ms、扩展 60000 ms、代码 600000 ms；Safe 常规 10000 ms、活跃 5000 ms；提前信号 1000 ms、CoW 10000 ms、资产/余额/仓位各 10000 ms；关联发现 86400000 ms（每分钟检查到期）；金库注册 1000 ms。

## 检查与验证

- 代码检查覆盖页面下载/条件请求、Factory 状态及事件队列、合约扫描、Safe 账户池/分页、提前信号各来源、WSS、历史游标、重组、通知去重/确认和运行状态输出。
- Windows 默认 Node 与生产同版本 Node.js 22.23.1 均通过 416 项测试；包括 30000 次信号释放回归、忽略取消的永久挂起、响应体超时、迟到响应、并发分页进度、池证据覆盖与通知满队列。
- 实际 Flap RPC 路径使用本地 HTTP 模拟节点进行压力验证，不消耗生产 RPC 配额；Node.js 22.23.1 完成 30000 次请求，堆内存 33.05 → 35.00 MiB，增长 1.95 MiB，结束时 active / queued / inFlight 均为 0。发布后观察将在下节记录。

## 外部限制

合约历史日志仍存在 `117817599 / 123897319` 的旧区间：现有节点返回 header not found 或超时。代码保留区间、失败退避和真实异常状态，不将无数据当补扫完成。解决完整旧历史覆盖仍需要有相应归档能力的节点。

公共节点的 429、访问拒绝与超时以及 Safe 上游额度属于外部限制；本轮不能保证供应商永不失败。现场观察只能验证其观察窗口，不代替跨数小时的稳定性证据。
