# Flap RPC 调度与恢复修复

版本：Monitor Suite 1.12.10 / Flap 1.10.9。时间为北京时间。

## 修复依据

2026/9/27 18:36 检查显示，自 17:08:50 启动后 Safe 记录 43 次预算失败，组成 39 段失败后恢复过程，恢复耗时 2.484–10.798 秒。nonce 的 8 请求批次与其他 Flap / Fourmeme 读取共享节点额度，普通请求不能动用优先预留，且一次失败阻断整轮 Safe API。Safe API 本身仍有可用账户，与 RPC 预算是两个系统。

同一观察期发生多次节点高度不齐：有明确错误表示请求区块比日志节点高 2 块。PublicNode 对无合约地址的发现查询要求指定地址，不能充当这些查询的有效备用。远端 WSS 曾以 1013 超时关闭后重连恢复；不把远端关闭归因为本地内存问题。

## 修改

1. Safe nonce 每批 2 项、并行上限 2，每轮仍覆盖全部 Safe，使用已有 `critical` 预留，不提高总预算。RPC 失败按批隔离，保留受影响地址的旧 nonce，不据旧值判断执行状态。新增 `lastNonceError`，与 API 错误分开；不会因 nonce 预算失败增加 API 退避，状态输出仍显示异常。
2. 实时日志将原空结果后的高度校验移到请求前。高度不足时尝试备用；Factory 可缩到已知可用高度，未知具体日志高度时最多逐块缩小重试 2 次，只有查询成功才提交返回的终点，未查尾部保留。
3. 无地址过滤器跳过已知不支持的 PublicNode 公共入口；其他节点明确要求地址时，将该能力限制记住 30 分钟。带地址过滤器仍可使用节点，不把发现查询改成仅已知代币查询。
4. WSS 重连后忽略旧 socket 的迟到事件，避免新订阅被旧 close/message/error 覆盖。已有心跳、重连和 HTTP 兜底保留。

## 不变项与边界

未修改监控调度间隔、确认块数、RPC 池、总额度、Safe API Key 策略或任何监控状态文件。旧合约区间放弃记录保留，提前信号历史补扫继续进行。

公共节点共同限流、上游故障或主动关闭 WSS 无法靠本地代码保证不再发生。本次修复内部预算准入、错误隔离及节点适配；若全部支持无地址查询的节点都不可用，保留游标并如实报告失败。

## 验证

回归覆盖：真实预算被普通流量消耗后 nonce 仍使用预留完成；单批失败不阻断其他 Safe、不触发 API 退避；实时高度预检和备用选择；Factory 缩小查询后只推进成功区间并继续追尾；节点能力限制不影响带地址查询；WSS 重连后的迟到旧连接事件隔离。

发布与生产观察结果将在验证后补充。
