# Four.meme 前端受限检查与修复

版本：Monitor Suite 1.12.28 / Four.meme 1.5.13。日期均为北京时间。

## 现场证据

2026/10/2 22:17–22:22 的服务器日志有 15 次 `[pool] 异常：HTTP 403`，899 条页面因域级退避跳过的日志，页面 HTML 直接返回 403 的日志为 0。底池请求为 `/meme-api/v1/public/config`。当时所有模块共用 `four.meme` 域级冷却，其他在途成功响应会将刚开始的 30 秒冷却缩短为 15 秒。页面每轮跳过仍增加失败计数，告警去重键包含不断增加的次数，导致同次故障反复提醒。运行指标却将吞掉页面错误的前端任务记为成功。

旧日志没有保存 403 响应正文、Retry-After 或 Cloudflare 标识，不能从这些日志确定具体防护规则；403 不应直接等同于 429。

## 修改

- 新增独立 HTTP 恢复控制器，仅适用于 Four.meme，RPC 调度不变。403 按 API、页面、静态资源范围隔离；429 保守使用主机范围，同主机不同服务范围一分钟内都被拒绝时升级为主机冷却。这是客户端的范围判断，并不是声称已知源站规则。
- Retry-After 支持秒数和 HTTP 日期；服务端指定等待较长时不被客户端五分钟上限截断。冷却期限不被在途成功响应缩短，等待调度的请求发出前再次校验。冷却到期逐个探测；至少三次成功且持续一分钟后清除故障状态，重复失败继续加长冷却。原有 5xx 重试耗尽后保留服务范围冷却。
- 同主机最多六个在途请求，既有 60ms 启动间隔不变。完全相同的同时 GET 合并，响应可独立读取；不同条件请求头、POST、带取消信号的请求不合并，不使用时间缓存代替检测。
- 底池和 API 探测统一公共请求头，避免同一个公开配置 GET 无法合并。
- 页面真实失败与冷却跳过分开统计，保留逐页最近成功时间和当前错误。故障事件持久化，同次故障只提醒一次；持续正常检查一分钟后发恢复消息。HTTP 模块不再单因跳过次数发恢复卡。
- 运行指标增加 HTTP 请求/复用/跳过/403/429/5xx 计数，以及限制来源路径、响应摘要、白名单响应头和下一次探测时间。重启加载已保存的 HTTP 冷却，不保存凭证或完整请求头。

## 频率与风险

本次不修改 `.env`、模块间隔或监控地址：服务器前端 5 秒、API 8 秒、底池 1 秒、模板 2 秒；其他模块保持原配置。源站明确拒绝期间仍需要冷却，无法保证与正常状态相同的实际采集速度。恢复后与旧基线继续比对，期间短暂出现又消失的中间状态无法保证补获。公共服务仍可能拒绝请求，本次修复客户端故障传播、恢复与告警问题，不绕过站点限制。
