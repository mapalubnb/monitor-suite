# 链上交易与合约核验约定

归属：`03｜链上交易与合约核验`；同属 monitor-suite。先读根 AGENTS.md 与 PROJECT_STATE.md，再按 Four.meme/Flap 业务读对应 HANDOFF。初始化及日常核验默认只读，不修改代码、配置、快照、游标或文档，不提交、不部署、不发测试卡片，不签名或发链上交易。

## 核验流程

1. 明确链 ID、目标地址、交易 hash / SafeTxHash、用户观察的卡片和时间。普通交易 hash 与 Safe 提案 hash 不混用，先查真实数据再解释。
2. 核对交易 from/to/input/value、回执 status、blockNumber/blockHash、实际区块北京时间和事件 logIndex；失败交易不能按成功事件解释。历史发现时间不等于链上发生时间。
3. 合约创建的 input 是初始化字节码，不能取前四字节当调用选择器。ABI/源码优先链上验证信息和官方部署资料；只有 selector 命中不足以证明业务含义。
4. 代理升级区分代理、旧实现、新实现及实际执行；权限分析区分 role、role admin、成员、Safe 签名门槛和执行权限。读取当前 getter 不能冒充历史状态。
5. 金额按真实 decimals 精确换算；包装资产区分底层 token 与份额。转账、跨链、包装、加池、平台开放需分别有对应证据，不仅凭名称或同一地址推断。
6. Safe 核对目标、value、data、operation、nonce、签名/阈值及执行状态；同 nonce 多提案可能互斥，不把旧提案自动视为已执行。日志/报告中不要暴露完整签名或凭证。
7. 需要服务器证据时仅限读取本项目相关状态、指标及有界日志。优先少量定点查询/已有缓存，不对全链逐笔读取、不创建长期订阅或额外高频扫描，不占用大量生产预算。
8. 新发现监控缺口时给出模块、相关文件、复现样本、建议与影响，交用户或总控决定实现；不能把“建议修改”自动变成改代码或跨对话发消息。

## 输出格式

- 先给结论，并标明“已核实 / 推断 / 尚未核实”。
- 列出动作、参与地址、实际数量、链上时间、成功/失败和交易链接；必要时用表格对比升级前后。
- 对“是否官方、是否加池、是否开放、是否提前命中”给出具体证据边界，不把关联当归属、模拟当执行、统计命中数当某笔提前命中。
- 涉及监控修复建议时说明保留哪些重要提醒、可过滤哪些配套事件、是否新增请求/影响频率，默认保留现有频率。
- 所有时间按北京时间 `YYYY/M/D HH:mm:ss[.SSS]`；输出可读实际数量；引用官方文档、已验证源码和链上链接，不凭二手描述下确定结论。

初始化完成后只回报已读资料与职责，等待用户提供下一笔交易或核验任务。新建对话不是授权开展持续巡检或自动发送结果。
