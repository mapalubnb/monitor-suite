## 通知与运行方式

- **飞书卡片**：展示变化内容和相关链接，长内容自动分片，完整差异可下载。
- **启动通知**：进程启动后独立发送单张卡片，后台更新首轮检查进度和异常数量；发送或更新失败会自动重试。Flap 日志记录启动卡片的发送结果，便于排查漏发。详细运行状态使用 `fm-status` 或 `fl-status` 查看。
- **可选 AI 分析**：先推送监控结果，再异步补充摘要；余额或凭证异常时暂停该提供商 30 分钟，基础通知继续发送。
- **实时与轮询结合**：链上模块使用 WSS 触发及 HTTP 兜底；页面、API、GitHub 和 Safe 服务按各自频率查询。
- **故障恢复**：实时扫描与历史补扫分别保存进度，实时扫描落后超过 2000 块时，保存未扫描区间并恢复最近 20 块扫描，旧积压进入补扫队列；失败退避并重试待发送通知。金库注册同样将实时与历史扫描分离；历史节点不可用时按区块范围保留缺口并退避，不阻塞实时扫描。状态命令分别显示实时延迟、连接状态和历史补扫异常。Factory 启动回扫限制在近期 5000 块内，较早区间由持续补扫处理。
- **机器人交互**：查询状态、查看日志、管理路由和执行远程运维命令，仅允许白名单用户操作。

默认情况下，Four.meme 高频配置模块每 2 秒检查，前端每 7 秒、API 每 10 秒；Flap 页面与 Factory 实时轮询为 1 秒。具体间隔、RPC、监听地址和功能开关见 [.env.example](.env.example)，实际延迟受确认块、网络和服务限流影响。

### 调整监控配置

编辑 `/root/monitor-suite/.env`，可修改监控频率、RPC 节点、监听地址及功能开关：

- **Four.meme**：前端默认 7 秒、最低 5 秒；API 默认 10 秒、最低 8 秒；底池、模板、合约和链上参数默认 2 秒、最低 1 秒。

- **源站限流**：适当增加检查间隔，或降低前端请求并发。

修改配置后重启并查看状态：

```bash

mon-status
```

## 1.11.0 RPC 分池与容量保护

1.11.3 补充：可选合约 getter 的整批 `execution reverted` 按逐项不可用处理，不误报为节点故障；严格读取仍失败并保留基线。真实批次失败会显示原始错误摘要，便于区分服务不可用、历史缺失和合约回滚。

1.11.2 补充：批量上限改为 8 个子请求，减少大批次等待整批预算时被小请求挤占的情况；实际请求总量仍按子请求计费。合约状态读取失败后，独立的实时事件扫描仍会执行并保存进度，避免状态服务故障阻断日志覆盖。实时合约事件落后超过 100 块时，每轮扫描上限暂增至 200 块（不超过配置上限），追平后回到 50 块；保持原检测周期与逐段成功提交，并显式使用实时节点池。

1.11.1 补充：`FLAP_RPC_BLOCK_URLS` 与 `FOURMEME_RPC_BLOCK_URLS` 可单独分配区块、头块及回执读取，留空沿用普通读取池。`bsc-dataseed-public.bnbchain.org` 实测不支持代码、存储槽与合约调用，不能作为通用读取节点；节点准入须逐方法验证。创建者原始区块读取同样拆分为最多 20 项，分段后仍校验整段父子块连续性。Safe 凭证池变更会解除旧请求来源的重试等待，但保留实际错误直到成功。

- Flap 可分别配置 `FLAP_RPC_READ_URLS`、`FLAP_RPC_REALTIME_URLS`、`FLAP_RPC_HISTORY_URLS`，Four.meme 可配置 `FOURMEME_RPC_READ_URLS`、`FOURMEME_RPC_LOGS_URLS`。空值兼容原节点列表；配置后每个池只在自己的列表内故障切换。历史池需包含足够独立且支持查询范围的服务，空历史日志仍需双源确认。
- 两个进程在 `.rpc-cooldowns/` 使用同一套令牌及在途租约。默认每个节点每秒 20 个子请求、突发 40、并发 4；历史最多占一个槽。批量拆为最多 20 项，按子请求数扣减。预算不足短暂等待后切备用，全部池容量不足会明确报错，绝不伪装成空结果或推进游标。
- `RPC_PROVIDER_LIMITS` 是按主机名索引的 JSON，例如 `{"rpc.example.com":{"rps":20,"burst":40,"concurrency":4,"group":"account-a"}}`。同账号不同域名必须使用相同 group 和额度配置；PublicNode 的 BSC 别名及 BNB 官方 dataseed 别名自动归并。配置额度不是服务商承诺，需结合实际吞吐与拒绝率调整。单次请求需在两分钟租约内完成；现有 RPC 超时均远短于该期限。
- 官方 BNB dataseed 不支持 `eth_getLogs`，只能放入普通查询池。分池与预算不会改变监控定时周期；实际完成延迟仍取决于节点容量，运行指标中的预算拒绝和等待时间用于暴露这一限制。
- Safe discovery 接入与提案相同的账户池，共享额度和冷却；失败后保留已完成的地址进度，避免每次重复消耗同一批请求。原 discovery 周期保持不变。快速回执重试时间及未设置重试时间的状态展示已修正。
- 公共服务的 429/403、历史裁剪及网络故障无法由客户端保证消失；本次修复隔离故障并控制本机流量，不自动增加付费服务或跳过历史缺口。

## 1.10.0 运行优化

监控间隔、WSS 通道和通知范围保持不变；实时缺口与历史补扫仍完整保留。

- 大快照改为 `snapshot.json` 小清单与同目录 `snapshot.json.parts/` 不可变内容文件。游标、待发送队列和大字段引用通过同一次原子替换提交，页面资源不再随每轮扫链重写；金库进度只更新自己的字段。首次写入自动迁移旧格式，读取失败停止启动，避免覆盖基线。
- **备份及迁移必须同时保留 `snapshot.json` 和 `snapshot.json.parts/`。** 旧代码不识别新格式；回滚前使用新版 `shared/snapshot-store.cjs` 的 `readSnapshot(path)` 展开为普通 JSON，或恢复升级前的完整备份。不要只复制清单文件。状态命令和机器人已兼容新旧格式。
- Flap 合并同时发生的相同 RPC 请求，备用竞速最多两路，节点并发有上限；仅链 ID 和 100ms 内的头块读数短暂复用，区块及回执校验保持新鲜。Four.meme 保留既有请求复用，两个进程通过 `.rpc-cooldowns/` 共享 429/401/403 冷却并遵守 Retry-After。历史范围不支持不会冷却近期查询。
- 历史日志按已配置历史池选择节点，明确的窗口/响应容量错误自动拆段；空和非空日志均采用首个成功节点，失败切换备用。公共节点无法提供的历史默认保留缺口；用户明确放弃的区间另行记录，不伪装成已扫描。实时与历史日志队列分配容量，防止历史长期得不到执行机会。
- 创建者反查按最多八个完整区块一批读取，仅查询实际部署交易的回执，不再批量下载所有交易回执；缺失区块或回执时保留游标。
- 修复快速信号重组误用历史游标的问题；按异常区块回退最近 128 块，保留更早事件和历史缺口。提前信号扫描使用 `FLAP_EARLY_MAX_BLOCKS`，合约历史扫描使用 `FLAP_CONTRACT_EVENT_MAX_BLOCKS`，不再被写死的 50 覆盖。
- 常驻与手动合约通知共用每批八条逻辑；发送成功后仅确认本批。修正资源下载计数，状态总览显示提前信号、合约事件的实时延迟。重复 RPC 错误日志合并计数。
