## 写入占用与交接

1. 所有仓库写入前，先用 `git rev-parse --absolute-git-dir` 获取 Git 目录，并检查 `git status --short`。
2. 用 Node `fs.mkdirSync(lockPath)`（**不带 recursive**）原子创建 Git 目录下的 `monitor-suite-write.lock`。`EEXIST` 表示已有写入者，不能覆盖。取得占用后创建 `owner.json`，写明对话 ID、职责、修改范围、开始时间；不写凭证。
3. 原子目录创建是互斥依据，文档中的“正在处理”文字不是锁。占用目录不进入 Git；它只协调同一工作目录，服务器变更仍统一由总控执行。
4. 锁存在时先读取所有者。保持只读，可以分析或准备方案；不要仅凭锁的年龄删除它。确认所属任务已结束/取消且没有写入后，由总控恢复遗留占用。
5. 结束时只删除自己创建的 `owner.json`，再用 `fs.rmdirSync(lockPath)` 删除空目录；所有者不符或目录内有未知文件时不删除，不使用递归强制清理。
6. 模块工作结束后更新 HANDOFF 的“待发布交接”，列出全部预期改动及验证证据，再释放占用。工作区有待发布改动时，后续写入只由总控接手或用户明确授权的同一任务继续；其他模块先做只读工作。
7. 总控取得占用后，核对 diff 与交接范围，只暂存本次已审查文件。不能用“提交全部”顺带收录其他对话工作。需要发送跨对话消息时先核对用户是否明确授权；默认由用户转交或总控读取，不自动互发消息。

初始化工作由总控取得占用，完成文档提交、服务器同步和对话登记后释放。锁状态始终以文件系统为准，不将本文件作为持续占用标记。

## 发布顺序与检查

1. 模块交接包括：问题及依据、文件列表、行为差异、测试结果、残留风险、配置/状态迁移、需要重启哪些服务。
2. 总控复核本地 `main`、工作区和远程分支，避免覆盖已有改动。必要时先 fetch 并处理远程新增提交。
3. 按改动运行 `npm run check` 与相关专项测试；共享逻辑或跨模块变更运行 `npm test`。纯文档只检查链接、配置引用、版本、`git diff --check`，不重跑无关业务测试。
4. 中文 Conventional Commits，推送 GitHub；用 `git ls-remote origin refs/heads/main` 确认待部署提交。推送失败就保留本地成果，不部署。
5. 服务器先检查跟踪文件无意外改动，备份本次涉及的代码版本、配置与必要状态，从 GitHub fetch 并 fast-forward 到已验证提交。保留用户未跟踪文件。
6. 只在运行代码、依赖、配置变更需要生效时重启对应服务。涉及状态修改时先停相关服务并备份；快照如果是分片清单，必须连同 `.parts/` 备份。
7. 发布后核对三方提交、服务进程、真实扫描推进、发送队列、错误与检测频率，记录观察窗口。短时无错不等于长期保证。

## 共同约束与数据边界

- 监控频率保持不变；区分调度周期、确认块数、服务端退避和真实通知延迟。不得通过跳过扫描、推进失败游标或丢队列伪装恢复。
- 公共 RPC/API 可能限流或暂不可用；不能保证“永不 429 / 永不断线”。先使用已有分工、限额、去重与恢复策略，不绕过供应商限制。
- 共享组件包括 `shared/rpc-control.mjs`、`rpc-budget.mjs`、`request-deadline.mjs`、`transactional-outbox.mjs`、`snapshot-store.cjs`、`feishu-client.mjs`、`card-markdown.mjs`、`display-format.cjs`、`ai-client.mjs`；更改需评估两个模块和机器人。
- 测试优先使用 `npm run test:fourmeme` / `npm run test:flap` 或 `node shared/run-tests.mjs ...`，避免直接导入生产模块触发 `.env`、发送或调度。只读回放需设置相应 TEST 模式和 `MONITOR_TEST_NO_ENV=1`，不向真实群发测试消息。
- Four.meme `snapshot.json` 使用内容寻址分片时通过 `shared/snapshot-store.cjs` 的 `readSnapshot()` 读取，不把 manifest 当完整业务状态；原子队列成功投递后才确认。
- 链上动作、提案、链上执行、最终确认、平台已开放是不同事实。金额按真实 decimals，用 BigInt 精确换算；未知精度与名称明确标识，首条通知不等待非必要补充查询。
- 所有展示时间使用北京时间 `YYYY/M/D HH:mm:ss[.SSS]`，尽量显示事件时间与发现时间；不要在卡片中输出字面 `**`、多余原始数量或误导风险结论。
