## 实现和边界

`vault-portal-v116.mjs` 集中管理已核实的角色、事件 ABI 和模块 getter。Grant 事件仅对 Portal 生效；角色管理和成员事件必须通过 ABI 字数及地址编码检查，错误数据保留原始 topics/data 供核验。

`contract-integrity-monitor.mjs` 沿用原采集链路，解析权限、授权事件并保留去重与重组处理。GrantUsed 仅在代理、交易 hash、区块 hash 都一致时合并审计报告；1.5 秒内未见报告则独立提醒。授权记录跟随现有最近事件窗口保存，不是永久全量事件档案。其他提醒不受关联窗口阻塞。

六个内部模块和撤销角色管理关系加入原核心扫描，增加七项批量 getter；新模块代码加入既有码审计。首次上线建基线，不把已有配置当成新变化。角色事件更新相应基线，避免下一轮 getter 重复报同一变更；迟到旧状态不能覆盖已观察到的新角色事件。

`operational-call-codec.mjs` 补充 Safe 迁移、撤销、状态查询和签名审计提交解码。签名提交包含动态 tuple 和字符串，错误编码回退为未知调用，原始 calldata 不丢失。解析不等于验签、审计安全结论或执行保证。

## 验证与发布

- 本地运行 `npm run check`、`npm test`；新增真实角色日志回放、来源隔离、畸形参数、授权与报告乱序合并、重启、重组、非阻塞投递、Safe 参数和模块基线测试。
- 先提交并推送 GitHub main，再确认远程确切提交，服务器快进更新；保留 `.env` 和运行状态并建立回滚备份。
- 仅重启 flap-monitor；Four.meme 与其他服务不重启。
- 本次已知漏掉的角色事件可在 Flap 停止期间按上述交易重新取得回执，核对来源、topic 和区块后定向补录到原持久队列；只移除该事件此前被未知事件过滤留下的去重记录，不能清空全部去重或回退所有扫描游标。
- 原检测频率不变。发布后检查七个 getter 基线、模块代码、WSS 连接、待发队列、最近日志及进程状态。

## 限制

新审计模块未取得公开验证源码，适配依据已验证主合约 ABI 和链上日志，并不构成对所有升级模块的安全审计。公共 RPC 和飞书外部服务仍可能限流或失败，沿用原重试与持久队列，不承诺长期无故障。
