## 入口与数据流

- `monitor.mjs`：API、前端、底池、OpenFour、合约/链上配置、创建者动作及模块调度。先定位相关实现再改，避免重构整个大文件。
- `http-recovery.mjs`：HTTP 风控分范围/主机冷却与恢复。
- `feishu-bot.mjs`：`fm-status` 等交互入口；同时可能涉及 Flap 状态卡，跨模块变更交总控。
- `monitor.test.mjs`、`http-recovery.test.mjs`：模块回归测试。
- 运行状态：`snapshot.json` 及 `.parts/`、`runtime-metrics.json`、`history.jsonl`、`diffs/`。历史文本可能截断、也可能在事务提交前产生，不能作为“已投递成功”的唯一证据。
- 采集 → 样本/状态稳定化 → 差异/动作分类 → 原子快照与 outbox → 飞书发送/重试。失败响应保留原基线，失败发送保留队列。

## 已确定的行为与降噪边界

1. 动态满池阈值 `totalBAmount` 仍采集保存，但数值变化不提醒；新增/移除底池、状态、费用、初始金额等照常检测。不能把所有目标金额硬编码为 10000。
2. API 仅使用有效响应更新结构；错误页/超时不能当删除字段。列表混合类型与空数组有保护，稳定类型变化连续三轮确认。
3. `data[0].filterId` 仅在代币列表端点按可选字段处理，出现/消失不提醒；保留类型基线和类型变更检测，缺失中断确认。其他结构字段仍监测。
4. 创建者只识别已关联创建者/手动配置的发起地址，不把收款人自动升级为官方；关联部署地址不代表所有后续新合约均属平台正式功能。
5. 部署交易标题为“部署新合约”，蓝色动作提醒；字节码不作为函数选择器，也不单凭部署认定高风险。权限/升级等原有告警保留。
6. 历史卡片带“历史补扫”，分别显示链上北京时间与本次发现时间；实时与历史共用 `actorNotificationLedger`，与 outbox 原子提交。保留待补扫区间凭证；区块 hash 不同的重新上链仍可提醒。
7. 回执严格匹配交易 hash、区块 hash、高度及状态，失败保留游标。`seenTxs` 旧记录只迁移已保存状态，不凭截断的 history.jsonl 静默跳过交易。
8. HTTP 403/429 依已有范围冷却与主机恢复规则处理，不用错误页面覆盖基线、不删除前端监测项来掩盖风控。详见 [HTTP 修复记录](../docs/fourmeme-http-recovery-2026-10-02.md)。
